# Replication Guide — Dezfouli & Thalmann Analyses

This document captures **everything an agent needs** to reproduce, for the
Dezfouli and Thalmann datasets, the analysis pipeline that produced the
synthetic-data publication figure (the 5-panel figure in
[final_plots/](final_plots/)).

The intent is that the same nested-CV infrastructure, the same canonical
retrain, the same dim-matched representational analyses, and the same
marginalised-environment rollout test (panel e) all carry over with minimal
changes.

> **⚠️ All pre-existing model results are invalid — retrain + retune from
> scratch.** Every model artifact produced before this replication (the
> free-z `nested_cv_winners/thalmann/`, `final_plots/thalmann/canonical/`,
> the older train-and-decode pipelines such as
> `plots_thalmann_s2_h10z3/`, and any analogous Dezfouli artifacts) was
> generated by a **flawed nested-CV implementation** and **must not be
> reused for any downstream panel**. There is no shortcut: hyperparameters
> must be re-searched and the per-fold + canonical models re-trained from
> scratch on a fresh `--hypothesis_z`-anchored namespace (e.g. `_z3`),
> and only those fresh canonical models may feed the decoding (b/c),
> three-regression (e), and held-out-NLL (a) analyses. Reusing cached
> latents, winners, or canonical checkpoints from the old runs is not
> permitted even when the HP point nominally matches.

> **Important scope decisions**
>
> 1. **The nested CV must be re-run from scratch** for both Dezfouli and
>    Thalmann. Do **not** reuse any pre-existing per-fold or canonical
>    artifacts in `runs_{dgp}_*` / `final_plots/{dgp}/canonical/` that
>    pre-date this replication — start with `stage_a_optuna` on a fresh
>    `--run_suffix`. The synthetic-pipeline configuration (z anchoring,
>    NLL-based HP selection + specificity-based seed selection, the
>    NLL-column fix) is the canonical setup; older runs may pre-date
>    these decisions.
> 2. **Panel d (environment decoding) is skipped for human data.** Do not
>    build an env-decoding analog. The composite figure for Dezfouli and
>    Thalmann is a 4-panel layout (a, b, c, e). Update the figure-script
>    grid accordingly.
> 3. **Selection protocol (always)**:
>    - **HPs** (stage_b winner inside each fold) → chosen by **minimum
>      inner-CV NLL** (`cv_val_loss`). The canonical retrain in stage_e
>      uses the modal HP combo across folds.
>    - **Seed** (stage_g, picks the top-1 canonical seed) → chosen by
>      **step1_specificity** for IDRNN, by NLL/`cv_val_loss` for Vanilla.
>      Pass `--metric step1_specificity` to stage_e.
> 4. **`--hypothesis_z` is a required up-front decision.** Before running
>    any SLURM stages, **the agent must ask the user** which z dimension
>    to anchor IDRNN to (synthetic used z=1, but the right value for
>    Dezfouli/Thalmann is a design choice). Do not silently default to
>    z=1 — surface the question, propose options (e.g. z=1, z=3, z=8 or a
>    free-z sweep), and only proceed after the user confirms.

The two main per-dataset adaptations are:

1. **Dezfouli** — the panel-e simulation study should decode **clinical diagnosis**
   (Healthy / Depression / Bipolar, see `data_dezfouli/df_train.csv` column
   `diag`) instead of a continuous learning rate. Use point-biserial / ANOVA F /
   logistic-AUC instead of Pearson r vs α.
2. **Thalmann** — the cross-task regret pipeline is **already wired up**;
   the agent only needs to plug the freshly-trained nested-CV canonical
   model into it.

## 2. The unified nested-CV pipeline

### Two-tier selection protocol (mandatory)

| step | what is chosen | by what metric | where in the pipeline |
|---|---|---|---|
| **HP selection** | best HP combo within each fold | **minimum inner-CV NLL** (`cv_val_loss`) | stage_b → modal combo in stage_e |
| **Seed selection** | best single seed of the canonical retrain | **step1_specificity** for IDRNN; `cv_val_loss` for Vanilla | stage_g (pass `--metric step1_specificity` to stage_e) |

This separation is load-bearing: HPs are tuned by predictive likelihood
(NLL), but the final canonical seed is picked by representational
specificity to avoid degenerate latents. Do not collapse these into a
single metric.

### Z anchoring for Dezfouli — headline is `--hypothesis_z 1`

The Dezfouli replication was run at z=1, z=2, and z=3 (full pipeline including
nested CV, full-101 canonical retrain, and the panel-e three-regression
analyses for each). The headline reported in the publication notebook
[dezfouli_publication_panels.ipynb](dezfouli_publication_panels.ipynb) is
**z=1**. The notebook has a `Z_DIM` parameter at the top of the setup cell
(default `Z_DIM = 1`) — set it to 2 or 3 to re-render the figures from the
alternative sweep without rerunning anything else; the data paths follow the
pattern `final_plots/dezfouli_z{Z_DIM}_full/`.

Why z=1 won the comparison on Dezfouli (n=101):

| metric | z=1 | z=2 | z=3 |
|---|---|---|---|
| Held-out IDRNN NLL per trial | **0.316** | 0.344 | 0.344 |
| Step-1 diag macro-AUC (panel b) | **0.637** | 0.560 | 0.608 |
| Diag classification accuracy | **47.5 %** | 40.6 % | 43.6 % |
| R3 IDRNN perseverance BF₁₀ H-B (panel e) | **101.4** | 52.5 | 50.6 |
| R3 IDRNN perseverance BF₁₀ H-D | **28.9** | 3.14 | 4.07 |
| Marginalisation gain R3 − R1 AUC | +0.007 | **+0.026** | −0.012 |

The user's a-priori intuition that perseverance is approximately
one-dimensional is empirically supported: z=1 is the smallest bottleneck
that gives the best predictive likelihood AND the strongest diag-decoding
evidence. z=2 still has the largest *marginalisation gain* (R3 > R1) and
the highest absolute R3 AUC, so it remains a defensible alternative
headline. z=3 has higher step-1 specificity (the HP selector) and the
most balanced per-class decoding but pays for it with NLL and panel-e
weakness.

For Thalmann the analogous z anchoring decision is open — surface options
(z=1, z=2, free-z) to the user as usual and only commit once they confirm.

### Panel e — R0 + bootstrap CIs

Beyond R1 (observed) / R2 (RNG-marg, exact env) / R3 (RNG + env marg), the
notebook also reports **R0** = a *single* rollout in the subject's own
inferred env with no RNG averaging. R0 sits between R1 and R2 on the
marginalisation ladder: it is the model's one-shot prediction of what the
subject would do, before any noise is averaged away. We compute it for
free as `rollout[0]` of the K=20 batch used for R2, so the additional cost
is zero. All four bars (R1, R0, R2, R3) get 2000-bootstrap-resample
95 % CIs on the LOO macro-AUC and stacked pairwise Bayes factors above the
bar — matching the bootstrap-r convention from
[synthetic_publication_panels.ipynb](synthetic_publication_panels.ipynb).

### Panel b accuracy benchmark

The notebook adds a second panel-b cell rendering **classification accuracy**
(LOO argmax-correct) alongside the existing macro-AUC variant. Two
reference lines (matching the style of the other chance lines in this
notebook):
- **Black dotted line at 1/3** — chance for a 3-way classifier.
- **Red dotted line at 52.5 %** — Dezfouli et al. (2019) Table 1 reports
  this as the *supervised* RNN classification accuracy on the full
  cohort (n=102, end-to-end trained on diag labels). Our unsupervised
  IDRNN-then-LR pipeline reaches 47.5 % at z=1 — within reach of the
  supervised benchmark despite never seeing diag labels during the IDRNN
  fit.

### Latent source for diag decoding & rollouts (Dezfouli/Thalmann)

For the **decoding analyses (panel b/c) and the three-regression
rollouts (panel e)** on human-data DGPs we use **step-1 lookup
embeddings**, not step-2 encoder outputs. Step 1 trains the decoder
against a free per-subject `nn.Embedding` (`LookupEncoderZ`); step 2
trains the IDRNN encoder to *distil* those embeddings from behavior.
On Dezfouli z=2 the step-2 encoder empirically collapsed to a near-
constant z across subjects (range ~0.16–0.19), so decoding from step-2
z gave below-chance AUC (0.31). Step-1 z (range ~−1.9 to 0.8) recovers
diag-decoding AUC 0.61 — comparable to or slightly better than
Vanilla h.

Rationale: held-out generalisation of the encoder is not needed when
the goal is representational analysis on the training cohort.
Step-1 z is the maximally informative per-subject latent the architecture
can represent at the chosen `z_dim`; using it isolates the
*representational-capacity* question from the *encoder-distillation*
question. For the **panel-e rollouts**, pair step-1 z with the
**pre-step-2.5 decoder checkpoint** (`epoch{N}_pre_step25.pt`) so the
decoder is the one that was trained against varied step-1 z — step 2.5
empirically updates ~8 decoder tensors and degrades the rollout match
between z and behaviour.

Concretely:
- Decoding (panel b/c): load `step1_z_lookup.npy` saved by `run_Q_model.py`
  alongside the canonical checkpoint dir.
- Rollouts (panel e): same z + pre-step-2.5 decoder weights (or an
  equivalent fresh `step2_5_epochs=0` retrain).
- Where to retrain the canonical model: **retrain on ALL participants**
  (concat the 70/30 train/test split into a single full-cohort training
  set). The 70/30 split is only relevant for held-out NLL evaluation; for
  representational analyses no held-out set is needed (one z per subject
  per the lookup). Back up `data_{dgp}/{xin,c,choice_one_hot}_{train,test}.npy`
  and `df_{train,test}.csv` before overwriting, then restore after the
  retrain completes so the nested-CV pipeline isn't disturbed. Fresh
  output dir: `final_plots/{dgp}_{tag}_full/canonical/{arch}/runs/`.

The held-out NLL panel (panel a) still uses the nested-CV per-fold
outputs (each subject is in exactly one fold's test set, so the full
population is covered once with proper held-out modelling).

### Per-key mode for canonical-HP aggregation (stage_e)

Stage_e has to collapse the **three** per-fold HP winners into **one**
canonical HP combo for the full-data retrain. The default
`modal_hp()` in [nested_cv/select_canonical.py](nested_cv/select_canonical.py)
tries (1) full-combo mode (a single combo wins ≥ 2 / 3 folds), (2) cross-fold
mean `cv_val_loss` over the entire grid, and (3) **fallback to fold-0's
winner**. With Optuna HP search only ~80 of the grid combos get tried per
fold, so step 2 almost always fails and the canonical retrain falls through
to fold 0's HPs — which may not be the best fold.

**Override with per-key mode** whenever the fall-through fires (and as a
preferred path for human-data DGPs in general). For each HP key, take the
mode of the values across the three per-fold winners; resolve ties (1/1/1
with no majority) by picking the value from the fold with the lowest
inner-CV NLL.

Why per-key mode is principled and non-leaky:

- **No test data anywhere.** Each fold's winner came from inner-CV NLL on
  that fold's *train* split; the aggregation across winners only touches
  inner-CV results. The outer test cohorts remain sealed.
- **Robust to a single bad fold.** A fold with a much worse NLL only gets
  one vote per key. The mode finds values ≥ 2 folds independently
  arrived at — a stronger signal than any single fold's combo.
- **Granular.** Full-combo mode demands unanimous-or-2/3 agreement at the
  row level (rare). Per-key mode tolerates folds disagreeing on *one or
  two* HPs while still aligning on most. Folds typically agree on the main
  architecture choices (`lmbd`, `hidden`, `epochs`) and disagree only on
  fine-tune flags like `step2_5_epochs`.

Things that *would* leak (and must not be used as alternatives):
- Picking the fold with the lowest *test* NLL.
- Picking the combo with the best test-set decoding accuracy.
- Picking the fold whose winner generalises best to other folds' test sets.

Worked Dezfouli z=2 example (per-fold winners by inner-CV NLL only;
folds 1+2 had NLL ≈ 0.12, fold 0 had ≈ 0.21):

| HP key | fold 0 | fold 1 | fold 2 | per-key mode |
|---|---|---|---|---|
| lmbd | 0.2 | 0.2 | 0.2 | 0.2 (3/3) |
| z | 2 | 2 | 2 | 2 (anchored) |
| hidden | 5 | 10 | 10 | **10** (2/3) |
| step1_epochs | 3000 | 3000 | 3000 | 3000 (3/3) |
| epochs | 1000 | 3000 | 3000 | **3000** (2/3) |
| step2_5_epochs | 400 | 0 | 400 | **400** (2/3) |

The original `modal_hp` fall-through would have used fold 0's
`hidden=5, epochs=1000` (the worst fold's combo). Per-key mode lands on
fold 2's combo at the row level, but each HP was decided by an independent
majority vote — fold 2 doesn't enter the rule by name.

**Operational note for the agent:** when stage_e's
`selection_reason` is `"fallback (fold0 winner)"`, do not accept it as-is.
Recompute the per-key mode from the per-fold winner JSONs at
`nested_cv_winners/{dgp}_{tag}/{arch}/foldN.json`, edit the spec at
`final_plots/{dgp}_{tag}_spec/canonical/{arch}_spec.json` in place
(`hp`, `hp_tag`, `selection_reason`), clean any partial canonical-runs
directory, and resubmit stage_f.

### Pre-flight decisions for the agent

Before running anything on a human dataset, the agent **must ask the user**:

1. **What value of `--hypothesis_z` should be used?** (Options: z=1 to
   mirror synthetic; a higher z=3/z=8; a free-z sweep with no anchor.)
   This decision determines the `--run_suffix` and the folder layout for
   every downstream stage.

Do not silently default. State the synthetic-pipeline choice (z=1) as a
reference, list 2–3 plausible alternatives, and wait for the user to
confirm before submitting any SLURM job.

All three DGPs (`dezfouli`, `thalmann`, `synthetic`) flow through the same
driver:

```bash
bash submit_nested_cv.sh <dgp> <stage> [extra args]
```

Source: [submit_nested_cv.sh](submit_nested_cv.sh). The package is
[nested_cv/](nested_cv/), with HP grids declared in

### Stages

| stage | what it does | runs on |
|---|---|---|
| `prep_synth` | (synthetic only) generates per-dataset fold dirs | CPU |
| `stage_a` | inner HP search (combo × fold × seed) | SLURM |
| `stage_a_optuna` | Optuna TPE HP search (preferred — uses shared SQLite study) | SLURM |
| `stage_b` | pick per-fold HP winners | CPU |
| `stage_c` | final per-fold runs with winning HPs (30 seeds × 3 folds) | SLURM |
| `stage_d` | test + outer-CV analysis | SLURM |
| `stage_e` | write canonical retrain spec (per-key mode across per-fold winners — see §2 "Per-key mode for canonical-HP aggregation"; override the default `modal_hp` fall-through to fold-0 when applicable) | CPU |
| `stage_f` | canonical full-data retrain | SLURM |
| `stage_g` | pick canonical seed (IDRNN: top-1 by step1_specificity; Vanilla: by val loss) | CPU |

### Typical end-to-end run (e.g. Dezfouli)

> **This must be run from scratch for both human datasets.** Use a fresh
> `--run_suffix` (e.g. `_z1_repl`) so the outputs do not collide with any
> pre-existing run directories. Do not reuse cached artifacts from earlier
> training sweeps.

```bash
bash submit_nested_cv.sh dezfouli stage_a_optuna --hypothesis_z 1 --run_suffix _z1_repl
# wait for SLURM
bash submit_nested_cv.sh dezfouli stage_b --run_suffix _z1_repl
bash submit_nested_cv.sh dezfouli stage_c --run_suffix _z1_repl
# wait
bash submit_nested_cv.sh dezfouli stage_d --run_suffix _z1_repl
# wait
bash submit_nested_cv.sh dezfouli stage_e --run_suffix _z1_repl --metric step1_specificity
bash submit_nested_cv.sh dezfouli stage_f --run_suffix _z1_repl
# wait
bash submit_nested_cv.sh dezfouli stage_g --run_suffix _z1_repl
```

Replace `dezfouli` with `thalmann` for the other dataset. The same stage names,
same flags, same outputs — only the underlying `DGPSpec` differs (HP grid,
fold layout, run-dir templates). Confirm the `--run_suffix` is threaded
consistently through every stage; the path-tag must be identical for
stages a–g to find each other's outputs.

### Key flags worth knowing

- `--hypothesis_z N` — anchors IDRNN's z_dim to N. **The agent must
  ask the user** which N to use before submitting any stage. Synthetic
  used z=1 (see [Synth z-bottleneck → alpha](memory/synth_z_bottleneck_alpha.md)
  memory: free-z picks z=8 → zero α decoding; **z=1 + NLL selection
  recovers α**). For Dezfouli/Thalmann the prior is unclear — surface
  options (e.g. z=1, z=3, full free-z) and **wait for confirmation**
  before launching SLURM.
- `--metric step1_specificity` — used in stage_e/stage_g. **Selects the
  final canonical seed by step1 specificity for IDRNN**, by NLL/cv_val_loss
  for Vanilla. (HPs themselves are still selected by NLL inside the folds
  — see the two-tier selection protocol in §2.)
- `--run_suffix _z1` — appends a tag to all run directories so you can keep
  multiple sweeps side-by-side. Bake the chosen z into the suffix
  (`_z1`, `_z3`, `_zfree`) so the path-tag is self-documenting.

### Panel a — held-out NLL

### Panel e — three-regression simulation study

This is the methods-novelty panel. See
[analyze_synthetic_three_regressions.py](analyze_synthetic_three_regressions.py).

**Three quantities per subject**:

- **R1** — observed mean per-trial regret (no model). For binary-reward
  environments: `regret_t = max(r_t^{(1)}, r_t^{(2)}) − r_t^{received}`.
- **R2** — exact-env rollout: replay the subject's own reward stream but
  let the *model* choose, conditioned on the learned representation
  $\hat z_i$. Average regret across $K=100$ Monte-Carlo rollouts.
- **R3** — marginalised-env rollout: sample fresh environments
  $\mathcal{E}_m \sim p(\mathcal{E})$ for $m=1,\ldots,M=100$ and average:
  $\widehat{R3}_i = \tfrac{1}{M}\sum_m \mathcal{S}(\hat z_i, \mathcal{E}_m)$.

R3 is the **generative-validity** statistic: it can only correlate with the
subject-level target if the representation, plugged back into the model's
forward dynamics, generates target-aligned behaviour in **counterfactual**
environments.

**Variants computed**:

- IDRNN — `z` as representation
- Vanilla — no representation (control; null)
- Vanilla+h(avg) — time-averaged hidden state, PC1-projected to match IDRNN's
  z_dim
- Vanilla+h(lastT) — last-timestep hidden state, PC1-projected (illustrates
  that the choice of h summary is a post-hoc heuristic)

**Test statistic**:

- Synthetic — Pearson r between R{1,2,3} and ground-truth α; BF via
  `pingouin.bayesfactor_pearson`.
- **Dezfouli — change the test statistic.** Diagnosis is categorical
  (Healthy/Depression/Bipolar, see `data_dezfouli/df_train.csv` column `diag`).
  Recommended:
  - For 3-way: ANOVA F (or Kruskal-Wallis if you prefer non-parametric) on
    R{1,2,3} grouped by diag.
  - For binary contrasts (e.g. Depression-vs-Healthy): point-biserial
    correlation, or AUC of R{1,2,3} as a one-feature classifier; Bayes
    factor via `pingouin.bayesfactor_ttest` on the two-group means.
  - Replicate the "3 pairwise BFs" pattern: IDRNN R3 vs Van+h_avg R3, IDRNN
    R3 vs Van+h_last R3, Van+h_avg R3 vs Van+h_last R3.
- **Thalmann** — already set up. See `analyze_cross_task_regret_s2.py`
  (cross-task regret pipeline); the "marginalised env" in Thalmann is
  fresh draws from `simulate_two_armed_bandit` (task 0) and
  `simulate_restless_bandit` (task 1). The test statistic is the
  correlation between rollout regret and a transfer target (e.g. task1
  horizon regret, or a fitted cog param).

**Adaptation checklist for the rollout script**:

1. **Generative environment sampler**:
   - Synthetic: `gen_reward_seq` (Bernoulli with reversal).
   - Dezfouli: the Dezfouli bandit is a two-armed task with structured
     reward schedules. The exact reward distribution should match the
     subject's own task — see `load_dezfouli.py`. If no generative model is
     available, sample $M$ envs as bootstrap-resamples of held-out subjects'
     observed env streams.
   - Thalmann: `simulate_two_armed_bandit` and `simulate_restless_bandit`
     are already in the repo.
2. **Encoder + decoder forward pass** must match the model's training-time
   input format. For Thalmann this includes the task embedding; for Dezfouli
   it includes the perseveration feature (and possibly step-2.5 if used).
3. **Per-session encoding**: encoder sees `xin_train` (the subject's full
   behavioural sequence) and produces $\hat z_i$.
4. **Rollout RNG**: keep distinct seeds per (subject, env, rollout). The
   synthetic script uses `seed = k * 9973 + s + offset` patterns — preserve
   reproducibility.
5. **PC1-match the h summary** before using it as h_init (`PCA(n_components=Z_DIM)`
   + `inverse_transform`).

## 7. Conventions to keep

- **Dimension-matching**: every representational analysis (RSA, R², PCA
  scatter, env-decoding, h_init for rollouts) must use the same effective
  dim — apply `PCA(n_components=Z_DIM)` + `inverse_transform` to Vanilla h.
  Inconsistency here invalidates the IDRNN-vs-Vanilla comparison.
- **z anchoring**: synthetic used `--hypothesis_z 1`. For the human
  datasets the agent **must ask** before launching. **HPs** are selected
  by inner-CV NLL; the **canonical seed** is selected by
  `--metric step1_specificity` (IDRNN) — keep both metrics in place.
- **Per-trial vs per-session NLL**: check units before plotting panel a.
- **Standalone panels**: save each panel as PNG **and** PDF in addition to
  the composite, with consistent colours (see top of
  [plot_publication_figure_nestedcv.py](plot_publication_figure_nestedcv.py)
  for the `COL_*` palette).
- **Bayes factors**: use `pingouin.bayesfactor_pearson` for correlations;
  `pingouin.bayesfactor_ttest` for group comparisons. Limit pairwise BFs to
  the 3 head-to-head tests in panel e (IDRNN R3 vs Van+h_avg R3, IDRNN R3 vs
  Van+h_last R3, Van+h_avg R3 vs Van+h_last R3); stack them with
  `h_step=0.085` to avoid overlap.

## 8. Smoke tests before scaling up

Before launching the full SLURM pipeline:

1. Run [_smoke_cross_task_regret.py](_smoke_cross_task_regret.py) — verifies
   the rollout RNG / encoder / decoder plumbing end-to-end.
2. For each DGP, do a single-fold dry-run of stage_a with `--dry_run` to see
   the sbatch commands.
3. Sanity-check the NLL fix: the held-out per-trial NLL on synthetic was
   ~0.50 (better than `log 2 ≈ 0.69` chance). On real data, expect values in
   a similar range — anything above `log K` where K is the number of choice
   options is a red flag.
